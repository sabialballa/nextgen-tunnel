# نصب جداگانه با کد اتصال، بدون SSH بین سرورها

این مسیر روی هر سرور از کنسول خودتان اجرا می‌شود؛ سرورها برای نصب به یکدیگر SSH نمی‌زنند. می‌توانید از کنسول پنل ارائه‌دهنده استفاده کنید. مسیر شبکهٔ تونل همچنان باید برقرار باشد: ترکیه/initiator باید TCP 443 ایران/listener را ببیند.

روی **هر دو سرور** با root این دستور را اجرا کنید:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/sabialballa/nextgen-tunnel/main/menu.sh)
```

## ۱. روی ایران

- گزینهٔ **10 — Install separately without SSH: pairing codes** را بزنید.
- نقش **1 — Iran / listener** را انتخاب کنید.
- IPv4 قابل دسترسی خود ایران و سپس IPv4 ترکیه را وارد کنید. آدرس ایران صریح پرسیده می‌شود تا IP پشت NAT حدس زده نشود.
- کد یک‌خطی با پیشوند `NGT1-I-` ساخته می‌شود؛ تمام آن را کپی کنید.
- پنجره را باز نگه دارید یا برای ادامهٔ بعدی Enter بزنید. هنوز لازم نیست ترکیه آماده باشد.

## ۲. روی ترکیه

- گزینهٔ **10** و نقش **2 — Outside Iran / initiator** را انتخاب کنید.
- کد ایران را در `Paste the listener invitation code` وارد کنید. برای خصوصی‌ماندن، هنگام چسباندن متن نمایش داده نمی‌شود؛ سپس Enter بزنید.
- تنظیمات و کلید خصوصی مستقل ترکیه خودکار ساخته می‌شوند و کد پاسخ با پیشوند `NGT1-R-` نمایش داده می‌شود.
- کد پاسخ را کپی کنید و اجازه دهید نصب ترکیه تمام شود. پیام انتظار برای طرف مقابل در این مرحله طبیعی است و به معنی تأیید اتصال نیست.

## ۳. دوباره روی ایران

- کد پاسخ ترکیه را در `Paste the initiator reply code` وارد کنید. اگر قبلاً خارج شده‌اید، دوباره گزینهٔ۱۰ و نقش۱ را بزنید؛ همان جفت ادامه پیدا می‌کند.
- نصب engine، Site-to-Site و GRE/VXLAN/IPIP روی ایران انجام و اتصال خصوصی IPv4، IPv6 و هر سه overlay بررسی می‌شود.
- روی ترکیه نیز گزینهٔ۱۰، نقش۲ و **1 — Resume/check this pair** را بزنید تا بررسی نهایی آن سمت انجام شود.

در پایان موفق هر دو سمت باید پیام `site and all overlay connectivity checks passed` را بدهند. اگر پیام `Peer connectivity is not yet confirmed` دیدید، نصب محلی باقی می‌ماند؛ ابتدا تکمیل نصب طرف مقابل، دسترسی TCP443 و وضعیت فایروال را بررسی کنید. راه‌انداز فایروال را خودکار باز نمی‌کند.

## کدها و ادامهٔ نصب

کد اتصال یک رمز کوتاه یا سرویس ثبت‌نام اینترنتی نیست؛ اطلاعات ضروری اتصال را در یک خط حمل می‌کند و هیچ پورت مدیریتی تازه‌ای باز نمی‌شود. کد دعوت شامل مجوز دسترسی client است؛ فقط از کنسول معتبر خودتان و یک مسیر مورد اعتماد کپی کنید. آن را در چت عمومی، گزارش خطا یا issue نگذارید. Base64 و checksum رمزنگاری نیستند و هویت فرستندهٔ دعوت را اثبات نمی‌کنند. پاسخ با HMAC-SHA256 به همان دعوت و کلید عمومی ترکیه متصل است؛ پاسخ جفت دیگر یا پاسخ تغییرکرده پذیرفته نمی‌شود.

دعوت برای ثبت اولیه ۲۴ساعت اعتبار دارد. اگر قبل از تکمیل ایران منقضی شود، اجرای دوبارهٔ گزینهٔ۱۰ روی ایران یک دعوت تازه می‌دهد؛ کدهای قبلی دیگر در آن سمت پذیرفته نمی‌شوند. روی ترکیه از **2 — Import a renewed invitation** استفاده کنید و پاسخ تازه را برگردانید. کلیدهای خصوصی عوض نمی‌شوند. اعتبار زمانی دعوت، پس از تکمیل نصب سرویس را منقضی نمی‌کند.

کلیدهای خصوصی WireGuard هر سمت و کلیدهای خصوصی CA/REALITY ایران از سرور سازنده خارج نمی‌شوند. فقط کدها را جابه‌جا می‌کنید؛ فایل JSON دستی لازم نیست. تنظیمات جفت در `/var/lib/nextgen-easy/console-pair.json` با مجوز `0600` و پوشهٔ `0700` ذخیره می‌شوند. اجرای دوبارهٔ همین جفت، کلیدها و engine نصب‌شده را حفظ می‌کند. نصب‌های دستی یا متعلق به مسیر SSH به‌طور حدسی تبدیل نمی‌شوند؛ وجود نصب قبلی باعث توقف می‌شود.

پیش‌نیازها مانند [نصب ساده](easy-install.md) هستند، با این تفاوت که OpenSSH و دسترسی root بین دو سرور لازم نیست. دسترسی به دانلود HTTPS، مخزن ابزارهای لازم، مقصد معتبر TLS1.3 و پورت TCP443 لازم است. خروجی اینترنت کاربران و اشتراک VPN خودکار ساخته نمی‌شوند.

[گزارش تست نصب با SSH مسدود](evidence/console-pair-install.json) مربوط به دو Linux محلی جدا است. این آزمون نصب، محدودیت پایداری UDP ثبت‌شده در [وضعیت پروژه](STATUS.md) را تغییر نمی‌دهد.

## اگر دریافت بسته متوقف شد

دریافت اولیه حدود۱۰۴MiB است. نسخهٔ جدید مقدار پیشرفت و سرعت را نمایش می‌دهد؛ timeout اتصال/خواندن۱۵ثانیه و بودجهٔ هر نوبت دریافت۳دقیقه است. پس از توقف یا Ctrl+C، همان گزینه را دوباره اجرا کنید تا فایل ناقص ادامه پیدا کند؛ ممکن است میزبان دانلود Range را پشتیبانی نکند و دریافت از ابتدا شروع شود. فایل‌های ناقص در cache می‌مانند، اما پیش از تطبیق SHA256 اجرا نمی‌شوند.

اگر GitHub از سرور قابل دسترسی نیست، [بستهٔ کامل ثابت](https://github.com/sabialballa/nextgen-tunnel/releases/download/v0.3.0-rc3/nextgen-tunnel-0.3.0-rc3-linux-amd64-full.tar.gz) را روی رایانه یا شبکهٔ دیگری بگیرید. فایل را از طریق ابزار بارگذاری ارائه‌دهنده یا مسیر مدیریتی خودتان با همین نام در این مسیر سرور قرار دهید:

```text
/var/cache/nextgen-menu/nextgen-tunnel-0.3.0-rc3-linux-amd64-full.tar.gz
```

اگر پوشه موجود نیست، با root بسازید:

```sh
install -d -m 700 /var/cache/nextgen-menu
```

سپس گزینهٔ۱۰ را دوباره اجرا کنید؛ بستهٔ بارگذاری‌شده به‌صورت محلی بررسی و استفاده می‌شود. نیازی به بازکردن SSH بین دو سرور نیست. آرشیو را دستی استخراج نکنید؛ نصب‌کننده checksum و manifest را بررسی می‌کند. تنظیمات و کلیدهای قبلی را حذف نکنید.

## خطای WireGuard با `fopen: Permission denied`

این خطا هنگام بازکردن فایل تنظیمات توسط `wg` رخ می‌دهد. پروفایل استاندارد [AppArmor برای wg](https://gitlab.com/apparmor/apparmor/-/raw/master/profiles/apparmor.d/wg) دسترسی فایل‌های تنظیمات را در `/etc/wireguard` مجاز می‌کند؛ استفاده از مسیر اختصاصی زیر `/var/lib/nextgen-sites` با این محدودیت سازگار نیست. برای تأیید قطعی دخالت AppArmor روی یک میزبان، گزارش DENIED کرنل همان میزبان لازم است.

نسخهٔ جدید تنظیمات را در یک فایل موقت اختصاصی زیر `/etc/wireguard` با مجوز `0600` می‌نویسد و بلافاصله پس از `wg setconf`، حتی هنگام شکست، همان فایل را پاک می‌کند. فایل‌های VPNهای دیگر دست‌نخورده می‌مانند؛ AppArmor غیرفعال و مجوز فایل کلید عمومی نمی‌شود. کلید اصلی و اطلاعات جفت حفظ می‌شوند. پوشهٔ موجود باید متعلق به root باشد و دیگران اجازهٔ نوشتن در آن نداشته باشند.

اگر نصب قبلی در همین مرحله شکست خورده، راه‌انداز جدید را اجرا و گزینهٔ۱۰، نقش قبلی و ادامهٔ همان جفت را انتخاب کنید. نیازی به ساخت دوبارهٔ کلیدها یا تغییر دستی JSON نیست. این اصلاح مسیر و پاک‌سازی فایل موقت تست دارد؛ آزمون کامل سیستم‌عامل Ubuntu 26.04 هنوز جداگانه تأیید نشده است.

اگر گزارش تازهٔ کرنل هنوز مسیر قدیمی `name="/var/lib/nextgen-sites/ngt-site-main/wg.conf"` را نشان می‌دهد، نسخهٔ اصلاح‌شدهٔ helper در آن تلاش اجرا نشده است؛ همچنین زمان گزارش را با آخرین تلاش مقایسه کنید. راه‌انداز جدید `Menu source revision` را چاپ می‌کند و دریافت شاخهٔ main را با درخواست بدون cache انجام می‌دهد. برای اجرای دقیق یک نسخه، متغیر `NEXTGEN_REVISION` را روی SHA کامل۴۰حرفی همان commit بگذارید؛ این انتخاب از checkout محلی قدیمی هم صرف‌نظر می‌کند. خود `menu.sh` را نیز از URL همان commit دریافت کنید تا راه‌انداز قدیمی از cache اجرا نشود. این روش نسخهٔ برنامه را مشخص می‌کند و تنظیمات جفت یا کلیدها را حذف نمی‌کند.
