# نصب سادهٔ دو سرور

روی **یکی** از دو سرور، با حساب root اجرا کنید:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/sabialballa/nextgen-tunnel/main/menu.sh)
```

گزینهٔ **۱** را بزنید و فقط دو مورد را وارد کنید:

1. نقش همین سرور: `1` ایران / listener، یا `2` خارج / initiator.
2. IPv4 طرف مقابل.

نقش سمت دیگر خودکار انتخاب می‌شود. نصب‌کننده از SSH به حساب root آن متصل می‌شود. کلید یا agent فعلی SSH قابل استفاده است؛ در غیر این صورت خود SSH رمز و در اولین اتصال تأیید اثرانگشت را می‌پرسد. اثرانگشت را با کنسول معتبر ارائه‌دهنده تطبیق دهید. رمز در فایل تنظیمات یا آرگومان برنامه ذخیره نمی‌شود. نقش‌ها فنی‌اند و انتخابشان الزاماً به کشور وابسته نیست.

پس از پایان موفق، engine، سایت خصوصی و GRE/VXLAN/IPIP روی هر دو سرور نصب و برای بوت فعال‌اند. برنامه اتصال IPv4، IPv6 و هر سه overlay را در هر دو جهت بررسی می‌کند. برای نصب سمت دوم منو را دوباره اجرا نمی‌کنید. ساخت یا ویرایش دستی JSON و انتقال دستی کلید لازم نیست.

## پیش‌نیازها

- دو سرور Linux amd64 دارای systemd و WireGuard؛ Python 3.10+ روی سرور آغازکننده، Bash و curl برای بازکردن منو. نصب واقعی این مسیر روی دو Debian 12 تازه آزمایش شده است؛ Ubuntu 22.04+ نیز پیش‌نیازهای لازم را دارد.
- دسترسی root از SSH بین دو سرور؛ پورت و مسیر SSH از تنظیمات معمول OpenSSH خوانده می‌شود. اسکریپت تنظیمات sshd را تغییر نمی‌دهد.
- پورت TCP 443 روی listener آزاد و از سمت initiator قابل دسترسی باشد. اینترنت برای دریافت بستهٔ ثابت و ابزارهای لازم و یک مقصد TLS1.3 با گواهی معتبر لازم است.
- IP قابل دسترسی خود سرور باید از مسیر مستقیم یا آدرس مشاهده‌شده توسط SSH قابل تشخیص باشد. شبکه‌های دارای NAT یا ProxyJump پیچیده ممکن است به مسیر پیشرفته نیاز داشته باشند.

ابزارهای نصب‌نشده از apt با `--no-upgrade` دریافت می‌شوند؛ سیستم ارتقای کلی پیدا نمی‌کند. فایروال، مسیر پیش‌فرض میزبان و خروجی اینترنت خودکار تنظیم نمی‌شوند. این نصب یک ارتباط خصوصی میان دو سرور می‌سازد؛ اشتراک کاربران یا فوروارد پورت سرویس‌های دلخواه را خودکار ایجاد نمی‌کند.

## کلیدها و اجرای دوباره

کلید خصوصی WireGuard هر سمت روی خود همان سرور ساخته می‌شود. کلیدهای خصوصی CA و REALITY متعلق به listener هم همان‌جا می‌مانند. فقط کلیدهای عمومی و حداقل اطلاعات احراز هویت client از کانال رمز‌شده و احراز‌شدهٔ SSH منتقل می‌شوند. اعتبارسنجی TLS غیرفعال نمی‌شود. رفتارهای SSH و TLS مطابق [راهنمای OpenSSH](https://man.openbsd.org/ssh_config) و [تنظیمات TLS موتور](https://sing-box.sagernet.org/configuration/shared/tls/) است.

داده‌های نصب در `/var/lib/nextgen-easy` با پوشهٔ `0700` و تنظیمات و کلیدهای خصوصی `0600` نگه‌داری می‌شوند. باینری‌ها از بستهٔ منتشرشدهٔ rc3 با SHA256 ثابت دریافت و بررسی می‌شوند؛ به پوشهٔ موقت منو وابسته نیستند.

اجرای دوباره برای همین جفت و همین نقش، کلیدها را حفظ می‌کند و engine سالمِ نصب‌شده را دوباره راه‌اندازی نمی‌کند. تغییر نقش، طرف مقابل یا فایل‌های ساخته‌شده باعث توقف می‌شود. نصب‌های دستی یا ناشناس به‌صورت حدسی جایگزین نمی‌شوند؛ برای آن‌ها از گزینه‌های پیشرفته استفاده کنید.

اگر نصب یا آزمون اتصال شکست بخورد، منابعی که همین اجرای جدید ساخته است برگردانده می‌شوند؛ نصب قبلی و کلیدهای تولیدشده برای ادامهٔ امن حفظ می‌شوند. اگر ارتباط SSH قطع شود، بازیابی سمت دور ممکن است تأیید نشود و این موضوع صریح گزارش می‌شود. خطای مرحلهٔ نصب، در صورت وجود، به‌صورت خصوصی در `/var/lib/nextgen-easy/last-error.log` همان سرور ثبت می‌شود.

## آزمون این مسیر

[گزارش بدون اطلاعات محرمانه](evidence/easy-install-pair.json) نصب واقعی روی دو VM جدا، اتصال سایت و هر سه overlay، اجرای دوباره از هر دو نقش و رد تغییر نقش بدون تغییر کلید یا فرایند engine را ثبت می‌کند. این آزمون نصب، تأیید کارایی یا پایداری بلندمدت UDP نیست؛ محدودیت ثبت‌شده در [وضعیت پروژه](STATUS.md) برقرار است.
