# Direct-path comparison and rc2 mitigation

The rc1 three-hour test recorded TCP carrier stalls without an engine restart. Its original evidence and failed acceptance remain in STATUS.md. The follow-up compared authenticated direct IPv4 TCP/UDP with tunneled IPv4/IPv6 TCP/UDP simultaneously in both directions. Management used the Windows Wi-Fi interface directly, bypassing the local VPN per socket.

The ten-minute baseline showed repeated direct TCP timeouts in the Iran-originating probe and more than 95% deadline loss for direct UDP on both nodes. Synchronized, header-only captures had zero kernel capture drops. In their common guarded window, 147 distinct authenticated UDP replies were observed leaving the Iran NIC and none matched at the Turkey NIC. This establishes nonarrival between those observation points; it does not identify the responsible provider, middlebox or DPI mechanism. A 500 ms UDP timeout measures deadline loss, not necessarily permanent packet destruction.

The rc2 initiator duplicates already encrypted WireGuard datagrams across two separate REALITY/smux TCP connections. Each carrier has independent bounded queues, socket readers and writers. WireGuard supplies authentication and replay rejection. A short keepalive maintains a usable return endpoint. No custom cryptography or public UDP relay was added. A transient, narrowly scoped firewall rule interrupted one owned carrier connection for 20 seconds; the other remained available and the rule was removed afterward. The recorded before/after firewall hashes match.

This mitigates an individual stalled TCP connection. Both connections still share the same physical route, and duplication increases upstream bandwidth. It cannot repair the underlying direct UDP path, guarantee operation during complete path failure, or establish general resistance to DPI.

The final acceptance run lasts 1800 real seconds on each server, with direct controls still running and no changes to the tested Go binary. Its exact counts, time bounds, source report hashes, carrier PID stability and controlled-fault result are in [paired-paths-rc2.json](evidence/paired-paths-rc2.json). Raw socket data, real addresses, packet captures and disposable test credentials are excluded from distributable evidence.

Local validation includes Linux race/vet, Python tests, a scan of the exact rc2 core, transactional installation/recovery tests and a real-core configuration regression for ordinary multiple UDP services. See [Linux race](evidence/linux-race-rc2-final.txt), [Python tests](evidence/linux-python-rc2-final.txt), [core scan](evidence/security-core-rc2-final.json), [installation](evidence/stack-installation-rc2.json), [final runtime](evidence/rc2-runtime-final.txt) and [multiple-service regression](evidence/multiservice-rc2.json). The full transaction suite preceded two startup guards; the final binary received race/vet, scan and real update/status checks. This is a release candidate, without independent audit or production certification.
