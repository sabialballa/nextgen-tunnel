# منوی نصب و مدیریت

متن منو، پرسش‌ها، وضعیت سرویس‌ها و پیام‌های نصب و خطا به انگلیسی نمایش داده می‌شوند. گزینهٔ۱ از SSH استفاده می‌کند؛ گزینهٔ۱۰ با کد اتصال و بدون SSH بین دو سرور است.

روی سرور Linux اجرا کنید؛ Go برای بازشدن منو یا استفاده از بستهٔ آماده لازم نیست. Python3، curl و Bash باید نصب باشند:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/sabialballa/nextgen-tunnel/main/menu.sh)
```

اگر مخزن را دانلود کرده‌اید:

```bash
bash menu.sh
```

منو با کاربر معمولی باز می‌شود. نصب سرویس یا ساخت تنظیمات سیستمی را از حساب root اجرا کنید؛ برای اجرای sudo می‌توانید اول اسکریپت را ذخیره و سپس اجرا کنید:

```sh
curl -fsSL https://raw.githubusercontent.com/sabialballa/nextgen-tunnel/main/menu.sh -o nextgen-menu.sh
sudo bash nextgen-menu.sh
```

## گزینه‌ها

1. [نصب سادهٔ هر دو سرور](easy-install.md): فقط نقش همین سرور و IP طرف مقابل را وارد کنید. SSH به root طرف مقابل وصل می‌شود، کلیدهای مستقل و تنظیمات را می‌سازد و engine/site و هر سه overlay را روی هر دو سمت نصب و تست می‌کند. ممکن است SSH رمز یا تأیید اثرانگشت بخواهد؛ رمز ذخیره نمی‌شود. ویرایش JSON یا انتقال دستی فایل لازم نیست.
2. آماده‌سازی پروفایل listener و کلیدها، carrier دوحاملی TCP، کلید محلی WireGuard و فایل Site-to-Site هر سمت. کلیدهای WireGuard را روی هر سرور جداگانه بسازید و فقط public.key را مبادله کنید. تنظیم client engine را امن به سرور initiator منتقل کنید؛ private key سرور و CA را منتقل نکنید. منو پیش از ساخت پروفایل، گواهی و نام TLS مقصد handshake را با TLS1.3 بررسی می‌کند؛ شکست این بررسی باعث توقف ساخت پروفایل می‌شود. پورت handshake پیش‌فرض۴۴۳ است و با پورت عمومی listener که در مرحلهٔ carrier برای هر دو سمت یکسان انتخاب می‌کنید، فرق دارد.
3. نصب/به‌روزرسانی یکپارچهٔ engine/site با carrier.json و site.json همان سمت، یا بازیابی تراکنش ناتمام. بررسی اولیه قبل از اعمال انجام می‌شود و فقط پس از نوشتن `yes` عملیات اعمال می‌شود.
4. نصب، وضعیت یا حذف GRE/VXLAN/IPIP داخل سایت موجود. آدرس زیرساختِ خصوصی دو سمت و آدرس overlay پرسیده می‌شوند؛ این گزینه به‌تنهایی سایت یا اتصال عمومی جدید نمی‌سازد. سرویس‌های ناشناس به‌صورت حدسی حذف یا جایگزین نمی‌شوند.
5. وضعیت سرویس‌های اصلی و overlayها.
6. probe هسته با client.json یا Ping محدود روی آدرس خصوصی سایت/overlay.
7. نمایش آخرین۶۰خط گزارش سرویس‌ها برای عیب‌یابی.
8. نصب، به‌روزرسانی، بازیابی یا حذف هستهٔ مستقل؛ این مسیر با engine/site جداست.
9. دریافت/بررسی بستهٔ آمادهٔ Linux x64؛ بدون ساخت باینری. SHA256 ثابت آرشیو، باینری‌ها و manifest بررسی می‌شوند. بستهٔ تغییرکرده اجرا نمی‌شود.
10. [نصب جداگانه با کد اتصال](console-pairing.md): روی هر سرور جدا اجرا می‌شود؛ کد دعوت ایران را به ترکیه و کد پاسخ ترکیه را به ایران کپی کنید. SSH بین دو سرور و ویرایش دستی JSON لازم نیست. کدها اطلاعات دسترسی دارند؛ خصوصی نگه دارید.
0. خروج؛ خروج از منو سرویس‌های نصب‌شده را متوقف نمی‌کند.

## داده‌ها و پیش‌نیاز نصب

بازکردن منو یا انتخاب خروج هیچ نصب یا تغییری در سرویس‌ها انجام نمی‌دهد. در اجرای مستقیم اینترنتی، ابتدا سورس همان revision در یک پوشهٔ موقت خصوصی دریافت می‌شود؛ مسیرهای آرشیو و اندازهٔ آن پیش از استخراج بررسی می‌شوند و پوشه پس از خروج پاک می‌شود. نصب از محتویات دانلودشدهٔ همین مخزن انجام می‌شود، نه اسکریپت ناشناسِ سرور دیگر.

در اجرای root، تنظیمات و کلیدهای ساخته‌شده در `/var/lib/nextgen-menu` با مجوز خصوصی و runtime دانلودشده در `/var/cache/nextgen-menu` نگه‌داری می‌شوند. این دو پوشه با خروج از منو حذف نمی‌شوند. نصب‌کننده‌های موجود، فایل‌های لازم برای سرویس را به مسیرهای مدیریت‌شدهٔ پایدار خودشان کپی می‌کنند؛ سرویس به پوشهٔ موقت راه‌انداز وابسته نمی‌ماند.

گزینهٔ۱ داده‌های خصوصی را در `/var/lib/nextgen-easy` نگه می‌دارد. کلید خصوصی هر سرور روی همان سرور ساخته می‌شود؛ فقط کلید عمومی WireGuard و اطلاعات ضروری اتصال client از SSH عبور می‌کنند. اجرای دوبارهٔ همین جفت کلیدها را عوض نمی‌کند؛ نصب دستی یا ناشناس جایگزین نمی‌شود.

نصب engine/site به systemd، iproute2 و wireguard-tools نیاز دارد. نصب ساده فقط ابزارهای لازمِ نصب‌نشده را از apt دریافت می‌کند؛ ارتقای کلی، تغییر فایروال، default route یا خروجی اینترنت انجام نمی‌دهد. باینری آماده فعلاً amd64 است؛ اجرای آن روی ARM رد می‌شود.

نقش listener/initiator الزاماً به کشور وابسته نیست؛ در تست‌های این پروژه initiator در ترکیه بوده است. [راهنمای engine/site](engine-site.md) و [راهنمای overlayها](overlays.md) جزئیات تنظیمات دو سمت را دارند. این رابط، وضعیت آزمایشی نسخه و محدودیت UDP ثبت‌شده در [گزارش تست](STATUS.md) را تغییر نمی‌دهد.
